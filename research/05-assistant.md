# Ассистент «Навигатор»: референсы → система состояний и движения → архитектура

## 1. Что изучено (и что нет)

| Источник | Что взято |

## 2. Визуальное направление

Ассистент — не «чат-виджет», а ещё один лист того же чертёжного комплекта.

- **Знак ассистента — «провод»**: проводник между двумя изоляторами. Это уже язык сайта (провода-разделители, «ток бежит жёлтым импульсом»), и он естественно показывает состояние: провис, натяжение, импульс, колебание.
- Палитра без новых цветов: бумага / графит / один сигнальный жёлтый. Единственное добавление — цвет аварии `#C8442B` для ошибок.
- Форма: прямоугольная панель с линией 1px (как лист и штамп), срезанный угол у «пластин» — кнопки, реплики пользователя, черновик заявки.
- Типографика: Geologica для текста и марок опор, IBM Plex Mono — только для статуса и служебных пометок (это аннотация, как на чертеже).
- Карточка опоры — миниатюра «чертёжного листа»: силуэт на миллиметровке со штриховкой земли, марка крупно, три ключевых числа под жирной линией.
- Без градиентов, свечения, стекла и скруглений.

## 3. Состояния и движение

Одна машина состояний (`src/assistant/machine.ts`) управляет строкой статуса, проводом и кнопками. В состояние можно войти только по реальному событию.

| Состояние | Чем вызвано | Провод | Статус |
|---|---|---|---|
| idle | — | провисает, неподвижен (цикл отрисовки остановлен) | готов |
| listening | `audiostart` распознавания | натянут; принимает форму живого сигнала микрофона (`AnalyserNode`). Нет доступа к сигналу — неподвижен, об этом сказано текстом | слушаю |
| transcribing | `speechend` | натянут, сигнальная линия | распознаю речь |
| processing | запрос отправлен / сервер сообщил об инструменте | по проводу бежит импульс, пока запрос в полёте | обрабатываю запрос / ищу в каталоге… |
| responding | пришёл первый фрагмент текста | каждый полученный фрагмент ответа пускает волну | отвечаю |
| speaking | `start` синтеза речи | каждую границу слова (`boundary`) провод «щиплется» | говорю |
| error | сбой запроса, микрофона | глубокий провис, пунктир, красный изолятор | ошибка |

Переходы: idle → listening → transcribing → processing → responding → (speaking) → idle; processing/responding → error; speaking → listening (перебивание); listening → idle (отмена). Страховки от «залипания»: тайм-аут запроса 65 с, тишина при распознавании 12 с, сторож синтеза речи (если движок не прислал `end`).

Токены движения (на кривых сайта `--ease-out`, `--ease-in-out`, `--ease-draw`): нажатие 140 мс · смена состояния 200 мс · перестройка 320 мс · раскрытие панели 420 мс, закрытие 240 мс.

- **Лаунчер → панель**: панель раскрывается `clip-path` из прямоугольника самого лаунчера и складывается обратно в него; содержимое входит со сдвигом 35 мс.
- **Ожидание**: три ромба загораются по очереди + название реального шага.
- **Стриминг**: готовые блоки не перерисовываются, обновляется только последний; курсор существует, только пока текст действительно приходит.
- **`prefers-reduced-motion`**: ничего не движется; состояние читается по цвету изолятора, сигнальной линии и тексту.
- **Телефон**: полноэкранный лист по высоте `visualViewport` (клавиатура не закрывает поле ввода), safe-area, блокировка прокрутки страницы, фокус внутри.

## 4. Архитектура

```
браузер                                   Vercel Function                    Anthropic API
src/assistant/                            api/chat.js  ← server/*.ts
  launcher  (в основном бандле)             handler      проверки, лимиты, SSE
  panel     диалог, состояния     POST →    orchestrator цикл «модель ↔ инструменты»  ⇄  messages.stream
  stream    разбор SSE          ← SSE       tools        8 инструментов, валидация
  actions   действия на странице            catalog      поиск по src/data/catalog.json
  voice     Web Speech API                  prompt       правила + сведения о компании
  wire      индикатор
```

- **Источник правды о каталоге** — тот же `src/data/catalog.json`, что рисует сайт. Отдельной базы и векторного хранилища нет: 112 структурированных записей ищутся обычным фильтром.
- **Сведения о компании** (≈1 страница, из презентации заказчика) лежат в системном промпте; RAG для такого объёма не нужен. Сведения о партнёрах помечены как сведения о партнёрах.
- **Инструменты**: `search_catalog`, `get_tower_details`, `compare_towers` (данные) · `open_tower_sheet`, `go_to_section`, `filter_catalog`, `open_comparison` (действия на странице) · `prepare_inquiry` (черновик заявки). Действия сервер только проверяет и передаёт странице; страница выполняет их через собственные элементы управления и возвращает в чат реальный результат («выполнено» / «не удалось»), который попадает в контекст следующего хода.
- **Заявка**: ассистент показывает черновик → посетитель нажимает «Перенести в форму» → заполняется только поле сообщения → имя, телефон и отправку делает сам посетитель в форме сайта. Личные данные в чате не запрашиваются.
- **Голос**: распознавание и синтез — средствами браузера, звук через сервер сайта не проходит.

## 5. Ограничения

- В каталоге нет цен, сроков и остатков; e-mail у компании в источниках нет — ассистент об этом говорит прямо.
- У опоры 1П35-2 в источнике масса «20,89 кг» — карточка и ассистент показывают предостережение.
- Распознавание речи: Chrome/Edge/Safari; в Firefox кнопка микрофона отключена с пояснением. На телефонах форма сигнала недоступна (микрофон нельзя разделить с распознаванием) — провод неподвижен, об этом сообщается.
