# Сайт ТОО «Энергоконструкция»

Одностраничный сайт: Vite + TypeScript, GSAP (ScrollTrigger, Flip), Lenis, Three.js (лениво), без фреймворка.

## Запуск
```bash
npm install
npm run dev        # разработка
npm run build      # сборка в dist/ (статические файлы, можно положить на любой хостинг)
npm run preview    # просмотр сборки на http://localhost:4319
npm run data       # пересобрать данные каталога, фото и карту из ../research
```

## Откуда контент
- **О компании** — только из презентации `ТОО_Энергоконструкция_презентация.pdf` (выжимка: `../research/01-client.md`).
- **Каталог опор (112 позиций)** — названия и характеристики из раздела «Металлические опоры ВЛ» сайта aspmk-519.kz (`src/data/catalog.json`).
  - **Чертежи** перерисованы в вектор 1:1 (`public/catalog/<slug>.svg`, скрипт `scripts/trace.py`): обводятся слои схемы — элементы опоры и все размеры (размерные и выносные линии, стрелки, цифры, H/h/L). Водяной знак и фон отброшены, цвета приведены к палитре сайта. Для «Линейки» и сравнения используется вариант только с опорой (`<slug>-t.svg`).
  - В источнике потерян символ диапазона в марках проводов («АС-70 ? АС-95») — при переносе заменён на «÷».
  - У опоры 1П35-2 в источнике масса «20,89 кг» — перенесено как есть, стоит уточнить.
- **Изделия (644 позиции: мачты, молниеотводы, порталы ОРУ, опоры контактной сети, свайные фундаменты, металлоконструкции 0,4–35 кВ)** — названия, таблицы и фактические сведения (чертёж, серия, масса, размеры, назначение) из каталога zavsk.ru (`src/data/products.json`, скрипт `scripts/build_products.py`; исходные страницы и картинки — в `../research/zavsk/`, в git и на сайт не попадают). Разделы выбраны по скринам заказчика и по продукции из презентации; что компания не производит — заказчик уберёт.
  - Не перенесено: цены, текст «как купить», название, телефон и город компании-источника, рекламные фразы. Железобетонные изделия (ПМЖ, МЖ, опорные плиты ОП) пропущены — компания делает металлоконструкции.
  - **Чертежи** перерисованы в вектор 1:1 (`public/products/*.svg`, `scripts/trace_items.py`, все сразу — `scripts/trace_all.mjs`); превью для карточек — `*-s.webp` (`scripts/thumbs.cjs` + `scripts/webp.py public/products -s`). Фото и 3D-рендеры не перерисовываются; из коллажей «фото + чертёж» (ВГМ, ВГН, ВМОН) взята только половина с чертежом. Одинаковые схемы под разными именами сведены в одну.
  - Если в источнике одна схема на всю серию (например, у ПМС-16…ПМС-35 — схема ПМС-30,5), на листе это подписано: «Схема серии… размеры этой марки — в таблице или по запросу». У 115 изделий схемы в источнике нет — на сайте «Чертёж по запросу».
  - Обновить: `python -I scripts/build_products.py ../research site` → `node scripts/trace_all.mjs ../research` → превью.
- **Фото** — вырезаны из слайдов PDF и приведены к единой цветокоррекции (`scripts/build_photos.py`).
- **Карта опыта** — схема: трассы проведены прямыми между пунктами из названий проектов (подписано на сайте).

## Ассистент «Навигатор»
ИИ-ассистент в правом нижнем углу: отвечает по сведениям о компании и по каталогу, показывает карточки опор, сравнивает, открывает чертёжный лист, переходит к разделам, готовит черновик заявки; есть голосовой режим. Дизайн и архитектура интерфейса: `../research/05-assistant.md`.

Ассистент работает на **локальных моделях через Ollama**. Облачный ключ не нужен; запросы к Anthropic и другим облачным LLM не отправляются, пока вы сами не выберете `ASSISTANT_PROVIDER=anthropic`.

### Где какая модель
| Где | Модель | Как выбирается |
|---|---|---|
| Локальная разработка (`npm run dev`) | `qwen3:8b` через Ollama | по умолчанию, без настроек |
| Опубликованный сайт (Vercel) | `gemini-3.5-flash-lite` через Gemini API | автоматически, если задан `GEMINI_API_KEY` и не задан `OLLAMA_BASE_URL` |
| Любое место | что указано | `ASSISTANT_PROVIDER=ollama｜gemini｜anthropic`, `ASSISTANT_MODEL=…` |

### Gemini на опубликованном сайте
- Ключ `GEMINI_API_KEY` читает только серверная функция `/api/chat`; он уходит в заголовке `x-goog-api-key` и не попадает ни в браузер, ни в ответы, ни в журнал.
- Модель по умолчанию — `gemini-3.5-flash-lite` (стабильная, есть бесплатный тариф; идентификатор сверен с документацией Google 12.10.2026). Другая — через `ASSISTANT_MODEL`.
- Используется Interactions API (`POST /v1beta/interactions`) со стримингом. Вызов инструмента продолжается по идентификатору взаимодействия, поэтому Google хранит взаимодействия: 1 день на бесплатном тарифе.
- На бесплатном тарифе Google использует содержимое запросов для улучшения своих продуктов — посетителям не стоит писать в чат личные данные (ассистент их и не запрашивает). На платном тарифе это отключено.
- Лимиты бесплатного тарифа задаются на проект и показываются в Google AI Studio; при превышении API отвечает 429, а ассистент показывает «Слишком много запросов». Инструменты, проверка фактов, лимиты хода и события для страницы — те же, что у локальных моделей.
- Проверка настоящим ключом (около десяти запросов): `GEMINI_API_KEY=<ключ> node scripts/check_gemini.mjs` — ответ потоком, поиск, уточнение, сравнение, чертёж, заявка, ошибка инструмента, вопрос о цене, неверный ключ.

### Запуск локально
```bash
ollama list                 # должны быть qwen3:8b и/или mistral:latest
npm install
npm run dev                 # сайт и /api/chat на одном адресе; модель — qwen3:8b через http://127.0.0.1:11434
```
Браузер обращается только к `/api/chat` этого же сайта; к Ollama ходит сервер, не браузер. Первый ответ после простоя медленный: модель загружается в память (у `qwen3:8b` около 10 с, у `mistral:latest` до 40 с), дальше она остаётся загруженной 30 минут.

### Переключение модели
Через `.env.local` (образец — `.env.example`) или переменную окружения:
```bash
ASSISTANT_MODEL=mistral:latest npm run dev
```
| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `ASSISTANT_PROVIDER` | `ollama` | `ollama` или `anthropic` |
| `ASSISTANT_MODEL` | `qwen3:8b` | точное имя из `ollama list` |
| `OLLAMA_BASE_URL` | `http://127.0.0.1:11434` (локально); на Vercel значения по умолчанию нет | адрес Ollama или шлюза перед ним |
| `OLLAMA_API_KEY` | — | токен шлюза (обычному локальному Ollama не нужен) |
| `ASSISTANT_TOOL_MODE` | `native` для `qwen3*`, `json` для остальных | способ вызова инструментов |
| `ASSISTANT_THINK` | выключено | `1` — разрешить `qwen3` рассуждать перед ответом (медленнее) |
| `OLLAMA_NUM_CTX` | `8192` | окно контекста, токены |

| `OLLAMA_KEEP_ALIVE` | `30m` | сколько модель остаётся в памяти после запроса |

Модель автоматически не переключается: какая указана, та и отвечает.

### Как модели вызывают инструменты
Инструменты одни и те же для любой модели (`server/tools.ts`): `search_catalog`, `get_tower_details`, `compare_towers`, `open_tower_sheet`, `go_to_section`, `filter_catalog`, `open_comparison`, `prepare_inquiry`. Модель только просит вызвать инструмент; сервер проверяет аргументы и выполняет вызов по настоящему каталогу.
- **`native`** — встроенный вызов инструментов Ollama. Проверен на `qwen3:8b`.
- **`json`** — два коротких шага: «диспетчер» с примерами, ответ которого жёстко ограничен JSON-схемой (инструмент с аргументами либо «ответить»), затем обычный потоковый ответ по результату инструмента. Нужен для `mistral:latest`: с нативным вызовом она инструменты не вызывала и выдумывала характеристики. В этом режиме на одно сообщение выполняется один инструмент.

Дополнительная защита для локальных моделей: строки, которыми модель имитирует служебные пометки интерфейса («[Показаны карточки…]», «Действие: …»), и самодельные таблицы до пользователя не доходят.

### Защита от выдуманных ответов
Честность ответа не держится на одном промпте: сервер проверяет модель детерминированно (`server/guard.ts`).
- **До вызова инструмента** убираются аргументы, которые модель добавила от себя: класс напряжения, высота или масса, которых посетитель не называл; количество в заявке, которого он не называл (цифры из марки вроде «П110-2» количеством не считаются); комментарий к заявке не его словами. Модели сообщается, что аргумент отброшен.
- **После ответа** текст сверяется с результатами инструментов, диалогом и сведениями о компании. Ищутся: размеры и массы, которых нет в источниках; марки, которых нет в каталоге; цены и сроки; e-mail, сайты и чужие телефоны; «заявка отправлена»; сообщение об успехе действия, которое не удалось; названия инструментов и куски инструкций. Если что-то найдено, ответ отзывается (событие `retract`) и заменяется коротким текстом из заранее написанных фраз — только то, что известно точно.
- Слова перед вызовом инструмента («Открываю чертёж…») тоже отзываются: остаётся только ответ, написанный после результата.
- Если ход оборвался ошибкой, уже показанный непроверенный текст убирается.

Границы проверки: она ловит узнаваемые виды неподтверждённых утверждений (числа с единицами, марки, деньги, сроки, контакты), а не любые. Число считается подтверждённым, если оно есть где-либо в источниках, без привязки к конкретной опоре и характеристике; утверждения словами («очень прочная», «подходит для севера») не проверяются.

### Проверка на живых моделях
```bash
node scripts/eval_local.mjs qwen3:8b mistral:latest       # базовый диалог из пяти шагов
node scripts/eval_scenarios.mjs qwen3:8b mistral:latest   # десять сложных сценариев, каждый дважды
EVAL_DIR=evals/results node scripts/eval_scenarios.mjs qwen3:8b   # то же с сохранением результата каждого сценария
```
Сохранённые результаты последнего прогона обеих моделей лежат в `evals/results/` (по файлу на сценарий: вопросы, события, тексты ответов, время, память).
Первый скрипт проводит диалог из пяти шагов, второй — десять сценариев (поиск по характеристикам, сравнение трёх опор, уточнение, смена выбора, вопросы без ответа в каталоге, ошибка инструмента, неоднозначный вопрос, длинный диалог, попытки увести от правил, заявка без домысливания) через настоящий обработчик запросов и Ollama. Результаты от 11.10.2026: `qwen3:8b` — 10 из 10 сценариев стабильно (20 из 20 прогонов), `mistral:latest` — 6 из 10 (13 из 20).

### Производительность и память (замеры 11.10.2026, RTX 4050 6 ГБ, 24 ГБ RAM)
`node scripts/profile_local.mjs qwen3:8b` печатает разбивку времени каждого запроса к модели и память.
- **Узкое место — скорость генерации: 12–13 токенов/с** (модель на 36% считается на CPU: 6 ГБ видеопамяти ей не хватает). Разбор промпта из кэша — 0,1–0,7 с, инструменты — меньше 1 мс, загрузка модели после простоя — 4–5 с плюс 3–6 с на первый разбор промпта.
- Поэтому время хода почти линейно зависит от длины ответа. Инструменты теперь сообщают модели, что данные уже на экране, и ответ после карточек сократился с 380–440 до 75–85 токенов: ход с инструментом — 9–10 с вместо 35–43 с; первая карточка появляется через 2–3,5 с.
- Окно контекста 6144 вместо 8192 скорости не даёт (13 токенов/с на том же промпте), поэтому оставлено 8192.
- Промпт с описаниями инструментов — около 4100–5100 токенов; на коротком промпте та же модель выдаёт около 20 токенов/с. Сокращение промпта — следующий возможный резерв, но оно затрагивает качество и пока не делалось.

**Память.** `qwen3:8b` в нативном режиме держит процесс модели на 7,1–7,2 ГБ (из них около 3,9 ГБ в видеопамяти) и не растёт. У `mistral:latest` в режиме `json` процесс растёт до 13,9 ГБ: сервер модели (llama-server внутри Ollama) хранит в оперативной памяти кэш состояний промптов с лимитом 8192 МБ и кладёт туда 0,5–0,9 ГБ каждый раз, когда запрос не продолжает предыдущий, а в этом режиме чередуются два разных промпта. Освобождается кэш только выгрузкой модели. Сценарный прогон делает это сам (`EVAL_MAX_MODEL_MB`, по умолчанию 9000) и держит в памяти одну модель; для постоянной работы на `mistral:latest` нужен запас около 14 ГБ или короткий `OLLAMA_KEEP_ALIVE`.

### Ограничения локального режима
- Один ход — до 4,5 минут (один запрос к модели — до 2,5 минут); одновременно обрабатываются два ответа, третий получает «подождите».
- В модель уходит последние ~6000 символов диалога: окно контекста 8192 токена, а правила и описания инструментов занимают около 4300.
- Ответ модели ограничен 1024 токенами.
- Если Ollama не запущен, ассистент показывает ошибку с кнопкой «Повторить» и ничего не выдумывает.

### Опубликованный сайт и модели на вашем компьютере
Функция на Vercel не может обратиться к `localhost` вашего ноутбука — это другая машина. Поэтому на Vercel адреса по умолчанию нет: без `OLLAMA_BASE_URL` ассистент честно показывает «не подключён», а остальной сайт работает.

Сам Ollama в интернет выставлять нельзя: у него нет авторизации. Безопасная схема:
```
посетитель → сайт на Vercel → /api/chat (функция) ──https + токен──▶ туннель ──▶ шлюз 127.0.0.1:11500 ──▶ Ollama 127.0.0.1:11434
```
1. На компьютере с моделями: `OLLAMA_GATEWAY_TOKEN=<длинная случайная строка> node scripts/ollama_gateway.mjs`. Шлюз слушает только `127.0.0.1`, требует токен, пропускает только `POST /api/chat` и `POST /api/show` и только для разрешённых моделей, ограничивает размер запроса и число одновременных ответов.
2. Опубликовать шлюз (порт 11500, не 11434) через туннель с HTTPS — например Cloudflare Tunnel или Tailscale Funnel. Порты на роутере не пробрасывать.
3. В Vercel задать `OLLAMA_BASE_URL=<https-адрес туннеля>` и `OLLAMA_API_KEY=<тот же токен>`.

Шлюз проверен локально (отказ без токена, с чужим токеном, на другие пути и модели; ассистент через шлюз отвечает). **Туннель и связка с Vercel не настраивались и не проверялись** — этой инфраструктуры пока нет. Что нужно учесть заранее:
- сайт будет отвечать, только пока компьютер включён, Ollama и шлюз запущены;
- у функции Vercel лимит 60 с (`vercel.json`), а холодный старт модели на ноутбуке дольше — первые запросы после простоя будут обрываться по времени; для стабильной работы нужен постоянно включённый сервер с GPU, где модель не выгружается, либо перенос самого `/api/chat` на этот сервер;
- встроенный ограничитель запросов живёт в памяти одного экземпляра функции; для публичного сайта включите rate limit для `/api/chat` в Vercel Firewall.

### Голос
Распознавание и озвучка — средствами браузера (Web Speech API): распознавание — Chrome, Edge, Safari; озвучка — системным русским голосом, мужским, если он есть в системе. Языковые модели (`qwen3`, `mistral`) речь не распознают и не синтезируют. Весь голос изолирован в `src/assistant/voice.ts` (`listen()` и `speak()`), остальной интерфейс от поставщика не зависит — нейросетевой синтез можно подключить, заменив реализацию `speak()`.

### Как устроено
- `server/` — исходники функции: `handler.ts` (проверки, лимиты, выбор провайдера, SSE), `orchestrator.ts` (цикл «модель ↔ инструменты» с лимитами), `ollama.ts` (адаптер локальных моделей), `tools.ts` (8 инструментов), `catalog.ts`, `prompt.ts` (правила и сведения о компании из презентации).
- `api/chat.js` — собранная функция для Vercel. Генерируется (`scripts/build_api.mjs`) и хранится в репозитории; тест `tests/bundle.test.ts` падает, если файл устарел.
- `src/assistant/` — интерфейс: `launcher.ts` (единственное, что в основном бандле), `panel.ts`, `machine.ts` (состояния), `wire.ts` (индикатор-«провод»), `voice.ts`, `actions.ts` (действия на странице), `stream.ts`, `markdown.ts`, `views.ts`.
- Пакет `@anthropic-ai/sdk` остаётся зависимостью: на нём работает необязательный провайдер `anthropic`.

## Структура
- `src/hero/` — сцена «Сборка»: SVG-чертёж (`hero.ts`) → 3D-опора из L-уголков (`scene.ts`, Three.js, грузится при первом взаимодействии).
- `src/tower/model.ts` — процедурная модель опоры (общая для SVG и 3D). Это иллюстрация, не конкретная марка.
- `scripts/trace.py` — векторная перерисовка чертежей опор 1:1.
- `src/catalog/` — «Линейка опор» (масштаб по H, фильтр по кВ, поиск, таблица, мини-карта), «Чертёжный лист» (`sheet.ts`), сравнение (`compare.ts`). Ссылка на опору: `#/opora/<slug>`. Раздел «Изделия» — `items.ts` (свой чанк вместе с данными), ссылка на изделие: `#/izdelie/<slug>`.
- `src/ui/` — провода с физикой (`wires.ts`), шейдер цинка (`zinc.ts`), карта (`map.ts`), форма, секции.
- `src/styles/main.css` — токены и все стили.
